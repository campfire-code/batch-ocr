# 批量图片 OCR

> 篝火出品 · 收录于篝火 App 应用区

离线识别，结果导出 Excel / TXT

![界面截图](docs/screenshot.png)

## 下载

到 [Releases](https://github.com/campfire-code/batch-ocr/releases/latest) 下载对应安装包：

| 电脑 | 文件 |
|---|---|
| Windows 10 / 11 | `batch-ocr_版本号_windows-x64-setup.exe` |
| Mac（Apple 芯片） | `batch-ocr_版本号_mac-arm64.dmg` |
| Mac（Intel 芯片） | `batch-ocr_版本号_mac-x64.dmg` |

第一次打开：
- **Windows**：如果弹出「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」。
- **Mac**：如果提示「无法验证开发者」，打开「系统设置 → 隐私与安全性」，在下方点「仍要打开」。

## 怎么用

1. 把图片或整个文件夹拖进窗口，支持 JPG、PNG、WebP、BMP、GIF（GIF 只识别第一帧）。
2. 选择「导出方式」：
   - **汇总成一张 Excel**（默认）：所有图片的结果放在一张表里，列为「文件名、行号、文字、置信度」；
   - **每张图一个 TXT**：每张图生成一个同名 `.txt`，一行文字一行；
   - **合并成一个 TXT**：所有图片的文字放进一个 `.txt`，每张图前面写「==== 文件名 ====」。
3. 图片里有上下颠倒的文字（比如拍倒了的单据）时，打开「纠正倒置的文字」。
4. 点「开始处理」。汇总文件在全部处理完后生成，默认保存在「下载 / 批量图片 OCR」。

**说明**
- 文字按阅读顺序输出：从上到下，同一行从左到右；同一行里离得远的两段文字之间加一个空格。
- 识别模型（PaddleOCR PP-OCRv4 移动版，约 16 MB）内置在软件里，不联网、不上传；第一张图会多花 1～2 秒加载模型。
- 适合截图、文档、票据、商品详情图这类印刷体文字。手写体、艺术字、很小或很模糊的字识别效果会差一些，结果请人工核对。
- 模型对中文字之间的空格不敏感，例如「工具箱 2026」常被识别成「工具箱2026」。
- 「最低置信度」默认 0.5：低于这个值的文字不输出。漏字多时调低，出现乱码时调高。
- 需要 macOS 13.3 或更高版本（识别引擎依赖较新的 WebAssembly 支持）；Windows 10 / 11 均可。

## 验收用例

把 `samples/` 文件夹拖进窗口：

| 操作 | 应得到 |
|---|---|
| 保持默认参数（汇总成一张 Excel），点「开始处理」 | `商品说明-截图.png` 显示「5 行：篝火开源工具箱2026」；`倒置的便签.jpg` 显示「没有识别到文字」（倒着的字被置信度过滤）；`损坏文件.jpg` 显示「失败：无法识别这张图片，可能已损坏或格式不受支持」。提示条末尾为「已汇总 2 张图共 5 行文字：…/OCR识别结果.xlsx」 |
| 打开 `OCR识别结果.xlsx` | 5 行数据，「文字」列依次为：`篝火开源工具箱2026`、`产品名称：不锈钢保温杯500ml`、`适用人群：上班族、学生、户外爱好者`、`保温时长：12小时以上`、`订单号3712024102300010001 实付￥128.50`，置信度都在 0.98 以上 |
| 打开「纠正倒置的文字」，导出方式选「合并成一个 TXT」，清空后重新拖入 `samples/` 处理 | 生成 `OCR识别结果.txt`，其中「==== 倒置的便签.jpg ====」下面两行是 `周五下午三点开会`、`记得带上十月销售报表` |
| 导出方式选「每张图一个 TXT」再处理一次 | 生成 `商品说明-截图.txt`（5 行）、`倒置的便签.txt`，不生成汇总文件 |

## 自己编译

需要 Node.js 22、pnpm、Rust。

```bash
pnpm install
pnpm test          # 单元测试
pnpm tauri dev     # 开发运行
pnpm tauri build   # 打包
```

界面框架在 `src/kit`（所有 campfire-code 工具共用），本工具的逻辑在 `src/tool`。
